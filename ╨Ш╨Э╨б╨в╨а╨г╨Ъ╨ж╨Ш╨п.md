## Порядок установки

### 1. Миграция БД

В Supabase: **SQL Editor → New query → вставить содержимое
`supabase/migrations/003_xrocket_payment_method.sql` → Run**.
Она разрешает метод `xrocket` в таблице `payments` и добавляет колонку
`xrocket_invoice_id` (id инвойса у xRocket строковый, в `invoice_id BIGINT`
не влезает — поэтому отдельная колонка).

### 2. Файлы

Скопируйте файлы из архива в репозиторий с сохранением путей.

### 3. Переменные окружения (Vercel → Project → Settings → Environment Variables)

```
CRYPTOBOT_API_TOKEN=...        # @CryptoBot → Crypto Pay → приложение → API Token
CRYPTOBOT_WEBHOOK_TOKEN=...    # секрет Webhook в настройках того же приложения
XROCKET_API_TOKEN=...          # @xRocket → Rocket Pay → приложение → API token (Pay API)
XROCKET_WEBHOOK_SECRET=...     # Pay API → приложение → Settings → Webhook secret
NEXT_PUBLIC_MANUAL_PAY_USERNAME=your_admin_username   # БЕЗ @
NEXT_PUBLIC_SITE_URL=https://ваш-домен.com            # нужен для callbackUrl Xrocket
```

### 4. Настройка CryptoBot

1. @CryptoBot → **Crypto Pay** → **My Apps** → ваше приложение → создать/скопировать **API Token** → в `CRYPTOBOT_API_TOKEN`.
2. В приложении включить **Webhooks**: указать URL
   `https://ваш-домен.com/api/payments/webhook` и задать секрет → в `CRYPTOBOT_WEBHOOK_TOKEN`.
   Подписка выдаётся автоматически по событию `invoice_paid`.

### 5. Настройка Xrocket

1. @xRocket → **Rocket Pay** → **Create App** → скопировать **API token** (Pay API) → в `XROCKET_API_TOKEN`.
2. В настройках приложения (**Settings → API Version**) выбрать **Current** — иначе вебхуки приходят в старом формате и не пройдут проверку подписи.
3. Там же взять **Webhook secret** → в `XROCKET_WEBHOOK_SECRET`.
4. Webhook URL в приложении можно задать `https://ваш-домен.com/api/payments/webhook-xrocket`,
   но даже если он не задан — код передаёт `callbackUrl` на уровне каждого инвойса, события придут сюда в любом случае.

### 6. Telegram Stars

Ничего настраивать не нужно — счёт приходит в чат с ботом (`sendInvoice`),
оплата подтверждается через `successful_payment` в общем вебхуке бота
(уже работает в `app/api/telegram/webhook/route.ts`).

### 7. Карта по реквизитам

- Реквизиты задаются админом командой `/setrequisites` в боте или в админ-панели.
- Если задан `NEXT_PUBLIC_MANUAL_PAY_USERNAME`: после создания платежа
  пользователь видит реквизиты и кнопку **«Написать администратору»**,
  ведущую на `https://t.me/<username>`; подписку админ выдаёт вручную
  (кнопки в боте после скриншота / админ-панель).
- Если переменная не задана — работает старый сценарий: скриншот чека боту,
  админ подтверждает кнопкой «✅ Подтвердить».

## Как это работает

| Метод | Создание | Подтверждение |
|---|---|---|
| `crypto` (CryptoBot) | инвойс через `createInvoice`, оплата в новой вкладке | webhook `/api/payments/webhook` → `invoice_paid` |
| `xrocket` (Xrocket) | инвойс через Pay API `POST /api/v1/invoices`, оплата в боте @xRocket | webhook `/api/payments/webhook-xrocket` → `invoice_status_changed: paid` |
| `stars` (Telegram) | `sendInvoice` в чат с ботом | `successful_payment` в общем вебхуке бота |
| `bank` (карта) | реквизиты + кнопка на `t.me/<username>` | вручную админом |

Проверка подписи вебхука Xrocket: HMAC-SHA256 от `{Signature-Timestamp}.{rawBody}`,
ключ — `XROCKET_WEBHOOK_SECRET` (используется как есть, без SHA256-хэша,
в отличие от CryptoBot), плюс защита от повторов по временной метке (5 мин).

Идемпотентность: `confirmPayment` из `lib/payments.ts` не выдаёт подписку
дважды — повторные вебхуки (`payment_status_changed` приходит вместе
с `invoice_status_changed`) игнорируются по статусу `paid`.

## Проверка

1. `npm run build` — сборка без ошибок.
2. Создать тестовый платёж на странице `/subscribe` каждым методом.
3. CryptoBot/Xrocket: в логах Vercel увидеть POST на соответствующий webhook,
   статус платежа в БД сменится на `paid`, подписка активируется.
4. Карта: платёж `pending` → админ подтверждает → `paid`.

## Тестовые сети

- **CryptoBot**: `CRYPTOBOT_TESTNET=true` + токен от @CryptoBotTestnetBot.
- **Xrocket**: есть тестовый бот @xrocket_testnet_bot; если нужен — переопределите
  базовый URL через `XROCKET_API_BASE` (тестовый хост берётся из бота) и выпустите
  тестовый токен.
